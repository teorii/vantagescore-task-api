# Task API

A small task management REST API built with FastAPI. Storage is in memory, so the data lives
only for the lifetime of the process.

## Requirements

Python 3.11 or newer (developed on 3.12).

## Setup

```bash
python -m venv .venv
```

Activate it: `source .venv/Scripts/activate` in Git Bash on Windows, `.venv\Scripts\Activate.ps1`
in PowerShell, or `source .venv/bin/activate` on macOS and Linux. Then:

```bash
pip install -r requirements.txt
```

## Run

```bash
uvicorn app.main:app --reload
```

Interactive docs: http://127.0.0.1:8000/docs

## Test

```bash
python -m pytest -q
```

## Endpoints

| Method | Path | Success | Errors |
|--------|------|---------|--------|
| POST | `/tasks` | 201 with the created task and a `Location` header | 422 if `title` is missing or blank, or the body has unknown fields |
| GET | `/tasks` | 200 with a page of tasks in creation order (see Pagination); `?completed=true` or `?completed=false` filters | 422 if `completed` is not a boolean, or `limit` or `offset` is out of range |
| GET | `/tasks/{id}` | 200 with the task | 404 unknown id, 422 malformed UUID |
| PATCH | `/tasks/{id}` | 200 with the updated task; only fields present in the body change | 404 unknown id, 422 blank or null `title`, null `completed`, or unknown fields |
| DELETE | `/tasks/{id}` | 204 with an empty body | 404 unknown id |

A task looks like this:

```json
{
  "id": "b5cb155f-d732-40f6-96d5-0b90159b11c4",
  "title": "Write the README",
  "description": null,
  "completed": false,
  "created_at": "2026-10-16T19:28:46.957148Z"
}
```

`id` and `created_at` are generated by the server and cannot be set by the client.

## Pagination

`GET /tasks` takes `?limit=` (1 to 100, default 20) and `?offset=` (default 0) and returns a page:

```json
{
  "items": [],
  "total": 42,
  "limit": 20,
  "offset": 20,
  "next_offset": 40,
  "previous_offset": 0
}
```

`total` counts the tasks that match the `completed` filter. `next_offset` and `previous_offset`
are `null` when there is no page in that direction, and an offset past the end returns an empty
page rather than an error.

## Errors

Every error response has the same shape, including validation errors, unknown routes, and
unsupported methods (which also keep their `Allow` header):

```json
{"detail": "title: String should have at least 1 character"}
```

## Layout

```
app/
  main.py           create_app(): wires the router and the error handlers
  models.py         Task, TaskCreate, TaskUpdate, TaskPage, ErrorResponse
  storage.py        TaskRepository protocol, InMemoryTaskRepository, the get_repository dependency, TaskNotFoundError
  errors.py         exception handlers that produce the {"detail": ...} shape
  events.py         background task that appends create and delete events to task_events.log
  routers/tasks.py  the endpoints
tests/
  conftest.py       TestClient fixture with a fresh repository per test
  helpers.py        create_task() used by both test modules
  test_tasks.py     behaviour of each endpoint
  test_errors.py    the error contract: validation messages, 404, 405, 422, 500
  test_pagination.py paging metadata and totals
```

## Design notes

- Storage sits behind a `get_repository` FastAPI dependency typed as the `TaskRepository` protocol.
  Tests override it with a fresh repository per test, and a database-backed class with the same
  methods could replace it without touching the routes.
- Storage raises `TaskNotFoundError` and an exception handler turns it into a 404. Routes never
  raise `HTTPException`, which keeps the unknown-route 404 handler unambiguous.
- `title` is validated by one constrained type (`strip_whitespace`, `min_length=1`) shared by the
  create and update models, so a whitespace-only title is rejected on both.
- PATCH applies only the fields present in the request (`exclude_unset`), so `{"description": null}`
  clears the description while omitting it leaves it alone. `title` and `completed` can be omitted
  but not set to null, and the repository re-validates the merged task before storing it.
- Handlers are `async def`. There is no I/O, so dict access stays on the event loop instead of a
  thread pool.
- Creating or deleting a task schedules a `BackgroundTasks` job that appends a timestamped line
  to `task_events.log`.
- `GET /tasks` returns a page envelope rather than a bare list. The repository exposes `count` and
  takes `limit` and `offset`, which map directly to SQL, and `next_offset` and `previous_offset` are
  computed fields on `TaskPage`, so the navigation arithmetic lives in one place.
